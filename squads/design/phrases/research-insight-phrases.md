# Research Insight Phrases

## Context

Frases prontas para articular insights de pesquisa de forma clara e impactante.
Um insight não é um dado bruto — é a interpretação acionável que conecta observação
a oportunidade de design. Estas frases ajudam a comunicar descobertas de pesquisa
para diferentes audiências.

**Aplicação:** Reports de pesquisa, apresentações de insights, design briefs
**Tom:** Evidence-Driven + User Advocate

## Phrases

### Apresentando dados quantitativos
- "[N]% dos participantes não conseguiram completar [tarefa] sem ajuda."
- "O tempo médio para [tarefa] foi [N] minutos — [X]x maior que o benchmark de [M] minutos."
- "A taxa de conclusão caiu de [X]% para [Y]% entre a etapa [N] e [N+1] do fluxo."
- "De [N] participantes, [M] mencionaram espontaneamente dificuldade com [área]."
- "O NPS para [fluxo/feature] é [valor] — [X] pontos abaixo da média do produto."

### Apresentando dados qualitativos
- "Nas palavras do participante: '[verbatim]' — essa frase resume o sentimento de [N] dos [M] entrevistados."
- "O modelo mental do usuário difere do nosso: para ele, [como o usuário entende] não é [como o sistema funciona]."
- "O padrão que emergiu das entrevistas é [tema]. [N] de [M] participantes expressaram variações disso."
- "Os participantes descreveram a experiência como '[adjetivo 1]', '[adjetivo 2]' e '[adjetivo 3]'."
- "A principal frustração identificada é [problema] — mencionada em [N] das [M] sessões."

### Transformando dados em insights
- "Os dados indicam que [observação]. Isso sugere que [interpretação]. A oportunidade é [proposta]."
- "Embora [X]% completem a tarefa, a maioria usa workarounds — sinal de que o fluxo não é intuitivo."
- "A correlação entre [variável A] e [variável B] sugere que [hipótese]. Próximo passo: validar com [método]."
- "O gap entre expectativa do usuário ([como espera]) e realidade ([como é]) é a raiz do problema."
- "Descobrimos que [segmento A] e [segmento B] têm necessidades diferentes em [área]. One-size-fits-all não funciona aqui."

### Conectando insight a ação
- "Baseado nesse insight, recomendamos [ação 1], [ação 2] e [ação 3], priorizados por impacto."
- "A oportunidade de design que emerge é: [oportunidade]. Impacto estimado: [métrica]."
- "Se endereçarmos [problema], a projeção é melhoria de [X]% em [métrica] — baseado em [benchmark/dado]."
- "Este insight valida a hipótese de [H] e invalida [H]. A direção do design deveria ser [recomendação]."

### Comunicando limitações
- "Este estudo tem amostra de [N] participantes — suficiente para identificar padrões qualitativos, insuficiente para generalizar."
- "Os resultados refletem [perfil do participante]. Podem não se aplicar a [outro perfil]."
- "Correlação observada, não causalidade confirmada. Próximo passo: [teste específico]."
- "O dado mais confiável é [X]. O dado que precisa de mais validação é [Y]."

### Recomendando próximos passos de pesquisa
- "Para validar esse insight, recomendo [método] com [N] participantes focando em [variável]."
- "O próximo round de pesquisa deve incluir [segmento] que não foi representado neste estudo."
- "Sugiro A/B test para quantificar o impacto de [mudança proposta] antes do rollout completo."

## Variations

- Para C-level: "O que descobrimos → O que significa → O que recomendamos" (3 frases)
- Para designers: insight detalhado com implications de design
- Para desenvolvedores: insight focado em comportamento esperado e edge cases
- Para relatório escrito: formato completo com metodologia e dados de suporte

## When to Use

- Apresentações de resultados de pesquisa de usuário
- Documentação de insights em design briefs e docs
- Sprint planning para priorizar baseado em evidência
- Comunicação com stakeholders sobre decisões data-informed
- Retrospectivas de projeto para documentar aprendizados
