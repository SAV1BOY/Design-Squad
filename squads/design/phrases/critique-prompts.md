# Critique Prompts

## Context

Frases prontas para facilitar e participar de sessões de design critique. Prompts
estruturados ajudam a manter o feedback construtivo, específico e acionável —
evitando comentários vagos como "gostei" ou "está estranho".

**Aplicação:** Design reviews, critique sessions, feedback assíncrono no Figma
**Tom:** Evidence-Driven + Pragmatic Builder

## Phrases

### Abrindo a critique (facilitador)
- "Hoje vamos avaliar [feature/tela] com foco em [critério]. O designer vai apresentar por [N] minutos e depois abrimos para feedback."
- "Lembrem: feedback sobre o trabalho, não sobre a pessoa. Sejam específicos e proponham alternativas."
- "O design está em estágio de [exploração/refinamento/spec final]. Calibrem o feedback para essa fase."
- "Critérios de avaliação para hoje: [usabilidade / consistência / a11y / viabilidade]."
- "Antes de comentar, uma pergunta: o que está funcionando bem neste design?"

### Pedindo clarificação
- "Qual foi o racional para escolher [pattern/componente/abordagem]?"
- "Essa decisão foi validada com dados de pesquisa ou é hipótese?"
- "Como esse componente se comporta em [edge case / viewport / estado]?"
- "O usuário chega nessa tela vindo de onde? Qual é o contexto prévio?"
- "Quais alternativas foram consideradas antes de chegar nessa solução?"

### Feedback positivo específico
- "A hierarquia visual está clara — meu olho vai direto para [elemento] que é a ação principal."
- "O uso de progressive disclosure aqui é eficaz — reduz carga cognitiva sem esconder informação."
- "A consistência com o design system está excelente — reconheço os patterns de [componente]."
- "O tratamento de empty state é completo — tem ilustração, copy explicativo e CTA."
- "A responsividade está bem pensada — a adaptação para mobile mantém a hierarquia."

### Feedback construtivo específico
- "A ação principal está competindo visualmente com [elemento]. Sugiro aumentar o contraste do CTA."
- "O fluxo tem [N] etapas — os dados de benchmark sugerem que [M] etapas seria ideal. Dá para combinar [etapas X e Y]?"
- "O feedback de loading não está explícito. O usuário não sabe se clicou ou se o sistema está processando."
- "O contraste de [elemento] está em [valor] — abaixo de WCAG AA. Alternativa: [cor com contraste adequado]."
- "Esse pattern é diferente do que usamos em [outra tela]. Há razão para a inconsistência ou podemos unificar?"

### Questionando decisões de design
- "Esse componente resolve o problema, mas já considerou [alternativa]? Pode ser mais simples."
- "Como isso escala quando o conteúdo é [muito longo / muito curto / dinâmico]?"
- "O que acontece se o usuário [ação inesperada / edge case]?"
- "Isso funciona para nosso power user, mas e para o usuário iniciante?"
- "Em mobile com teclado aberto, essa interação ainda funciona?"

### Fechando a critique
- "Resumindo: os consensos são [lista]. Os pontos em aberto são [lista]."
- "Action items: [lista com owners e prazos]."
- "O designer leva o feedback e traz versão atualizada em [data/sprint]."
- "Há algum blocker que impede o design de avançar? Se não, próximo checkpoint em [data]."

## Variations

- Em critique assíncrona (Figma comments): usar formato "[TIPO] Observação → Sugestão"
- Em critique rápida (15 min): focar apenas em blockers e critérios de aceite
- Em critique de exploração: feedback sobre direção, não sobre detalhes pixel-level

## When to Use

- Critique sessions semanais do Design Squad
- Design reviews com stakeholders cross-funcionais
- Feedback assíncrono em Figma e ferramentas de design
- Avaliação de proposals e concepts em estágio inicial
- QA visual antes de handoff para desenvolvimento
