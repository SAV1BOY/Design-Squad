# Component Documentation Patterns

## Pattern Description

Padroes para documentacao de componentes em design systems. Boa documentacao e a diferenca entre adocao e abandono de um design system.

## Examples

### Example 1: Carbon (IBM) — Comprehensive Docs
Carbon documenta cada componente com:
- Overview com descricao e quando usar
- Live playground interativo
- Props/API table completa
- Variantes com exemplos visuais
- Accessibility guidelines especificas
- Figma embed com link para library

### Example 2: Polaris (Shopify) — Context-Rich Docs
Polaris inclui contexto de negocio:
- "Best practices" com do/don't visual
- Exemplos contextualizados (checkout, admin)
- Content guidelines (UX writing para cada componente)
- Related components com justificativa
- Changelog integrado ao doc

### Example 3: Primer (GitHub) — Developer-First Docs
Primer foca em desenvolvedores:
- Code snippets copiáveis para cada variante
- Storybook embed com controles interativos
- Props documentation auto-generated
- Accessibility checklist por componente
- Bundle size e performance notes
- Migration guide entre versoes

## Analysis

Documentacao eficaz de componentes:
- **Playground**: demo interativa para experimentar props
- **Do/Don't**: exemplos visuais de uso correto e incorreto
- **API completa**: todas as props com tipo, default e descricao
- **Accessibility**: guidelines e checklist por componente
- **Contexto**: quando usar e quando NAO usar
- **Searchable**: busca que encontra por nome, tag ou uso
