# IBM Carbon Design System Journey

## Overview

A evolucao do Carbon, design system open-source da IBM, de um projeto interno a uma referencia da industria em documentacao e acessibilidade.

## Timeline

### 2015-2016: Northstar → Carbon v1
```
Origem:
- Northstar era o antigo DS interno da IBM
- Fragmentacao entre 300+ produtos IBM
- Cada produto com visual e patterns proprios
- Decisao executiva de unificar
- Carbon nasce como rewrite completo
```

### 2017: Carbon v9 — Open Source
```
Lancamento open source:
- React component library publica
- Design guidelines abrangentes
- 40+ componentes enterprise-grade
- Acessibilidade WCAG AA como requisito
- Documentacao considerada benchmark
```

### 2018-2019: Carbon v10 — Design Tokens
```
Evolucao arquitetural:
- Token system introduzido
- Theming (white, g10, g90, g100)
- Grid system responsivo (16 column)
- Icon library (pictograms e icons)
- Figma kit oficial
- Community contributions formalizadas
```

### 2020-presente: Carbon v11+ — Mature System
```
Estado atual:
- Web Components (lit-element) alem de React
- Carbon for IBM Products (enterprise extensions)
- Design tokens em JSON (Style Dictionary compatible)
- AI/ML pattern library
- Accessibility-first culture
- 100+ componentes mantidos
```

## Documentation Excellence

```
Aspecto               | Implementacao
----------------------|------------------------------------------
Component docs        | Usage, Style, Code, Accessibility tabs
Pattern docs          | Context, examples, rationale
Guideline depth       | Cada topico com do/don't e rationale
Tutorials             | Step-by-step para novos contributors
Changelog             | Semantic versioning com migration guides
Search                | Full-text search em toda documentacao
```

## Accessibility Leadership

```
Pratica                     | Detalhes
----------------------------|------------------------------------------
WCAG AA requirement         | Todos os componentes devem atingir AA
Accessibility checklist     | Integrada a cada component page
Screen reader testing       | JAWS, NVDA, VoiceOver obrigatorios
Color contrast tools        | Integrados ao design toolkit
Keyboard patterns           | Documentados por componente
DAP (IBM Equal Access)      | Ferramenta propria de teste
```

## Lessons

- Open source constroi autoridade e comunidade
- Documentacao e tao importante quanto o codigo
- A11y como requisito (nao nice-to-have) eleva a qualidade geral
- Enterprise DS precisa de extensoes por produto (Carbon for IBM Products)
- Temas multiplos (4 temas) requerem tokens robustos desde o inicio
