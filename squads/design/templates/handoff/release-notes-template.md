## Instructions (Como Usar)

1. Preencha apos o release ser finalizado e testado.
2. Escreva em linguagem acessivel ao usuario final — evite jargoes tecnicos.
3. Destaque o valor para o usuario, nao os detalhes de implementacao.
4. Inclua visuais (screenshots, gifs) para features novas.
5. Valide com PM e Marketing antes de publicar.

> **Dica:** Release notes boas contam uma historia de melhoria. O usuario deve terminar de ler pensando "que legal, mal posso esperar para usar".

## Example (Parcialmente Preenchido)

**Headline:** "Novo filtro avancado e dashboards personalizaveis ja estao disponiveis"
**Feature 1 — Filtro Avancado:** Agora voce pode combinar multiplos filtros (data, status, responsavel, tags) para encontrar exatamente o que precisa. Em testes, usuarios encontraram itens 3x mais rapido.
**Melhoria:** Velocidade de carregamento de listas melhorada em 45% para contas com 1000+ itens.
**Fix:** Corrigido bug que impedia exportacao de relatorios em PDF no Safari.

## Notes

- Escreva para o usuario, nao para o time tecnico.
- Use linguagem positiva e orientada a beneficio.
- Screenshots e gifs aumentam significativamente o engajamento com release notes.
- Nao liste todos os bugs corrigidos — destaque apenas os que impactam significativamente o usuario.
- Coordene a publicacao com Marketing para maximizar alcance.
- Mantenha historico de todas as release notes para referencia.
