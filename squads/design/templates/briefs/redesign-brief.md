## Instructions (Como Usar)

1. Preencha este brief para qualquer redesign significativo (nao para ajustes pontuais).
2. Apresente o brief para stakeholders e obtenha aprovacao formal antes de iniciar.
3. Use a secao "Estado Atual" como baseline para medir o impacto do redesign.
4. Atualize o brief conforme decisoes sao tomadas ao longo do processo.
5. Ao concluir, documente os resultados na secao final.

> **Dica:** Redesigns sem metricas de sucesso claras tendem a se arrastar. Defina KPIs antes de comecar.

## Example (Parcialmente Preenchido)

**Produto:** Dashboard de Analytics
**Tipo de redesign:** Estrutural + Visual
**Trigger:** NPS caiu de 45 para 28 nos ultimos 2 trimestres; 60% dos tickets de suporte sao sobre dificuldade de encontrar dados.
**Principio 1:** "Dados certos no momento certo — sem cliques desnecessarios"
**Meta:** Aumentar task completion rate de 62% para 85% em 3 meses pos-lancamento.

## Notes

- Documente o "antes" com screenshots e gravacoes — voce vai precisar para comparacao.
- Considere um periodo de transicao onde ambas as versoes coexistem.
- Comunique o redesign para CS/Suporte com antecedencia para preparar a base de conhecimento.
- Faca validacao com usuarios reais antes de commitar com a implementacao completa.
- Revise este brief semanalmente durante o redesign para manter alinhamento.
