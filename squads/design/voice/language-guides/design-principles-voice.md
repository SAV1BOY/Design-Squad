# Design Principles Voice

## Context

Guia de linguagem para articular, comunicar e evangelizar os princípios de design
do produto. Design principles são as regras fundamentais que guiam decisões —
precisam ser memoráveis, acionáveis e diferenciadores. Um bom princípio de design
muda comportamento; um ruim é ignorado.

A voz dos princípios precisa ser firme sem ser dogmática, inspiradora sem ser vaga,
e prática sem ser restritiva. Cada princípio deve funcionar como filtro de decisão:
quando o time está em dúvida, os princípios resolvem o empate.

**Aplicação:** Definição, comunicação e aplicação de design principles.
**Tom predominante:** Creative Explorer + Evidence-Driven
**Frequência:** Definição anual, aplicação diária

## Do's

### Escrever princípios acionáveis
- "Mostre, não conte" — guia decisão concreta sobre quando usar visual vs. texto
- "Priorize a tarefa principal" — cada tela tem uma ação primária clara
- "Falhe graciosamente" — erros são oportunidades de ajudar, não becos sem saída

### Incluir tensão produtiva
- "Simples, não simplista" — define onde está o equilíbrio
- "Consistente, não uniforme" — permite variação com critério
- "Rápido para o usuário, cuidadoso nos detalhes" — nomeia o trade-off

### Acompanhar com exemplos de aplicação
- Para cada princípio, 2-3 exemplos de como ele se aplica no produto real
- Mostrar antes/depois de decisões guiadas pelo princípio
- Incluir counter-examples: situações onde o princípio NÃO se aplica

### Tornar memoráveis
- Frases curtas (máximo 6 palavras no título)
- Ritmo e sonoridade que facilitam lembrança
- Metáforas quando ajudam a fixar o conceito

### Validar com o time
- Princípios são cocriados, não impostos
- Workshop de validação: "este princípio muda alguma decisão que vocês tomam?"
- Se todos concordam facilmente, provavelmente é genérico demais

## Don'ts

### Princípios genéricos que qualquer empresa usaria
- "Foco no usuário" — óbvio demais, não diferencia
- "Qualidade" — não é acionável
- "Inovação" — não ajuda a decidir entre opção A e B

### Princípios contraditórios sem hierarquia
- Ter "Velocidade" e "Perfeição" sem dizer qual prevalece quando conflitam
- Listar 15 princípios sem priorização (ninguém lembra)
- Mudar princípios a cada trimestre (perdem credibilidade)

### Linguagem passiva ou burocrática
- "Deve-se considerar as necessidades do utilizador" — passivo e vago
- "É recomendável que as interfaces apresentem consistência" — burocrático
- "O design deverá seguir as melhores práticas" — não diz nada

### Princípios sem exemplo de aplicação
- Frase bonita na parede que ninguém sabe aplicar no dia a dia
- Princípio que não resolve nenhum dilema real
- Afirmação que não pode ser testada ou medida

## Templates

### Template de princípio de design
```
## [Título do Princípio — máximo 6 palavras]

**Em uma frase:** [Explicação expandida em 1 sentença]

**Por que isso importa:** [Contexto — qual problema esse princípio resolve]

**Na prática:**
- Exemplo 1: [Situação real + como o princípio guia a decisão]
- Exemplo 2: [Situação real + como o princípio guia a decisão]

**Counter-example:**
- [Situação onde este princípio NÃO é o critério principal]

**Teste:** [Pergunta que o time pode fazer para verificar se está seguindo]
```

### Template de workshop de princípios
```
## Workshop: Design Principles — [Data]

### Preparação
- Cada participante traz 3 decisões de design difíceis recentes
- Listar os princípios atuais (se existirem)

### Exercício 1: Dilemas (30 min)
- Compartilhar decisões difíceis
- Agrupar por tema

### Exercício 2: Draft de Princípios (30 min)
- Escrever princípios que resolveriam os dilemas
- Votar nos mais impactantes

### Exercício 3: Stress Test (30 min)
- Testar cada princípio contra cenários reais
- Refinar linguagem

### Output
- 3-5 princípios validados
- Exemplos de aplicação para cada um
```
