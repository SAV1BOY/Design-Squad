# Portfolio Case Study Writing

## Context

Adaptação de voz para escrita de case studies de portfolio — documentos que contam
a história de um projeto de design de forma narrativa, demonstrando processo,
pensamento crítico e impacto. Case studies são usados para showcase interno do squad,
avaliação de performance e referência para futuros projetos.

Diferente de docs técnicos, case studies são narrativos. Contam uma história com
início (problema), meio (processo) e fim (resultado). A voz deve ser envolvente
sem ser autoindulgente, técnica sem ser árida.

**Canal:** Wiki interna, portfólio do squad, apresentações de resultados
**Audiência:** Liderança, outros squads, novos membros (onboarding)
**Formalidade:** Nível 3-4 (Profissional a Formal)
**Tom:** Evidence-Driven + User Advocate + Creative Explorer

## Case Study Structure

### 1. Cover / Hero
- Título impactante que comunica resultado, não processo
- Bom: "Reduzindo abandono de checkout em 23%"
- Ruim: "Redesign da página de checkout"
- Visual hero: Screenshot principal ou before/after
- Metadata: Squad, período, papel do designer

### 2. Overview (TL;DR)
- 3-4 frases que resumem problema, abordagem e resultado
- Números de impacto quando disponíveis
- Duração do projeto e tamanho do time

### 3. O Problema
- Contexto de negócio: por que isso importava
- Dados que evidenciam o problema (métricas de baseline)
- Impacto no usuário: como o problema se manifestava na experiência
- Citações de pesquisa se disponíveis

### 4. Discovery e Research
- Métodos utilizados e razão de escolha
- Principais descobertas (insights, não raw data)
- Personas ou perfis de usuário envolvidos
- Frameworks de análise utilizados

### 5. Ideação e Exploração
- Como as ideias foram geradas (workshops, brainstorms, benchmarks)
- Alternativas exploradas — mostrar o caminho, não apenas o destino
- Critérios de decisão para convergir
- Mostrar rascunhos e evolução (processo é tão valioso quanto resultado)

### 6. A Solução
- Apresentação detalhada do design final
- Rationale para decisões-chave
- Como a solução endereça os insights de pesquisa
- Considerações de acessibilidade e escalabilidade
- Protótipos ou demos interativos quando possível

### 7. Validação
- Testes de usabilidade e resultados
- Iterações baseadas em feedback
- A/B tests se aplicável

### 8. Resultados e Impacto
- Métricas quantitativas: conversão, NPS, task completion, etc.
- Feedback qualitativo: citações de usuários
- Impacto no negócio: receita, custo, eficiência
- Reconhecer limitações e atribuição

### 9. Learnings
- O que funcionou bem e seria repetido
- O que seria feito diferente com o conhecimento atual
- Contribuições para o design system ou processos do squad

## Writing Rules

### Narrativa
- Escrever em ordem cronológica — respeitar a jornada do projeto
- Mostrar dificuldades e pivots — credibilidade vem da honestidade
- Usar citações diretas de stakeholders e usuários
- Verbos no passado para o que aconteceu, presente para insights duradouros

### Visual
- Proporção 60% visual / 40% texto
- Screenshots com annotations que guiam o olhar
- Before/after para mudanças impactantes
- Gráficos simples para métricas (linha do tempo, barras de comparação)
- Nada de Lorem Ipsum — conteúdo real

### Métricas
- Sempre comparar com baseline: "de X para Y" (não apenas "atingimos Y")
- Incluir período de medição: "após 30 dias do lançamento"
- Ser honesto sobre atribuição: "contribuiu para" vs. "causou"
- Arredondar para comunicar, não para enganar

## Common Mistakes

- Focar apenas no resultado bonito sem mostrar o processo
- Omitir falhas e iterações (parece fabricado)
- Excesso de texto sem visuais (fadiga de leitura)
- Métricas sem baseline (números fora de contexto)
- Não creditar o time (design é colaborativo)
- Case study de 40 páginas (ideal: 8-12 páginas ou 15-20 slides)

## Templates

### Template de slide deck (15 slides)
```
1. Cover: Título + visual hero
2. Overview: TL;DR em 4 bullets
3. O Problema: Contexto + dados
4. Research: Métodos + key insights
5. Insight Principal: A descoberta que mudou a direção
6-7. Exploração: Alternativas e evolução
8-10. A Solução: Telas principais + rationale
11. Acessibilidade: Considerações de a11y
12. Validação: Testes + iterações
13. Resultados: Métricas de impacto
14. Learnings: O que levar para o próximo projeto
15. Créditos: Time envolvido
```
