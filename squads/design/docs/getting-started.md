# Getting Started

## Overview

Guia de primeiros passos para novos membros do Design Squad. Este documento cobre
tudo que você precisa saber para se tornar produtivo rapidamente: ferramentas,
processos, canais de comunicação, e onde encontrar cada tipo de informação.

O onboarding completo leva aproximadamente 2 semanas. Na primeira semana, foco em
configuração e contexto. Na segunda, foco em primeiro projeto com pair design.

## Content

### Semana 1 — Configuração e Contexto

#### Dia 1-2: Ferramentas e Acessos
1. **Figma** — Solicitar acesso ao time de design via admin
   - Instalar Figma Desktop (não usar apenas browser)
   - Plugins obrigatórios: Figma Tokens, Stark (a11y), Content Reel
   - Localizar as libraries: DS Core, DS Icons, DS Illustrations
2. **Slack** — Entrar nos canais do design squad
   - #design-squad (interno), #design-reviews, #design-system
   - #produto-geral, #engenharia-frontend
3. **Jira/Linear** — Acesso ao board do squad
4. **Confluence/Notion** — Acesso à wiki de design
5. **GitHub** — Acesso ao repositório do design system (read)

#### Dia 2-3: Contexto do Produto
- Ler o `squad-overview.md` para entender missão e escopo do squad
- Ler o `agent-roles-guide.md` para entender seu papel e dos outros agentes
- Assistir gravação da última sprint review (link no canal #design-squad)
- Navegar o produto como usuário — criar conta, explorar fluxos principais

#### Dia 3-4: Design System
- Explorar o design system no Figma — componentes, tokens, patterns
- Ler a documentação de componentes no Storybook
- Entender a naming convention (`naming-conventions.md`)
- Criar uma tela simples usando apenas componentes do DS (exercício prático)

#### Dia 4-5: Processos
- Ler o `workflow-guide.md` — fluxo de trabalho do squad
- Ler o `design-review-standards.md` — como reviews funcionam
- Ler o `handoff-standards.md` — como entregar para desenvolvimento
- Participar da primeira daily como observador

### Semana 2 — Primeiro Projeto

#### Dia 6-7: Pair Design
- Ser pareado com designer sênior para primeiro projeto real
- Observar uma design review completa
- Receber feedback no primeiro artefato de design

#### Dia 8-9: Primeira Entrega
- Completar primeira tarefa do sprint com supervisão
- Receber code review do design (review de Figma)
- Participar da primeira critique session como feedback provider

#### Dia 10: Check-in
- Reunião de check-in com design lead
- Listar dúvidas acumuladas
- Definir objetivos do primeiro mês

### Checklist de Onboarding

- [ ] Acessos configurados (Figma, Slack, Jira, Wiki, GitHub)
- [ ] Plugins do Figma instalados
- [ ] Libraries do design system vinculadas
- [ ] Docs fundamentais lidos (squad-overview, roles, workflow)
- [ ] Produto explorado como usuário
- [ ] Exercício de design system completado
- [ ] Primeira design review observada
- [ ] Primeira tarefa completada com pair
- [ ] Check-in com design lead realizado

### Onde encontrar ajuda

| Dúvida sobre | Onde perguntar |
|---|---|
| Design system | #design-system no Slack |
| Processo e fluxo | Design lead ou #design-squad |
| Ferramentas | #design-squad — thread de tooling |
| Acessos e permissões | Admin de TI ou manager |
| Produto e features | PM do squad |
| Implementação | Dev lead do squad |
