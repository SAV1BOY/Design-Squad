# Glossary

## Overview

Glossário de termos técnicos utilizados pelo Design Squad. Termos em inglês mantidos
no original quando são padrão da indústria. Definições em PT-BR para clareza.

## Content

### A

- **A11y** — Abreviação de "accessibility" (a + 11 letras + y). Acessibilidade digital.
- **ADR (Architecture Decision Record)** — Documento que registra uma decisão de arquitetura, seu contexto e consequências.
- **Affordance** — Propriedade de um elemento que sugere como ele pode ser utilizado. Um botão com sombra "parece" clicável.
- **ARIA (Accessible Rich Internet Applications)** — Conjunto de atributos HTML que melhoram a acessibilidade para tecnologias assistivas.
- **Audit** — Avaliação sistemática de uma interface contra critérios definidos (ex: WCAG audit, DS audit).

### B

- **Benchmark** — Análise comparativa com concorrentes ou referências do setor.
- **Bounce rate** — Percentual de visitantes que saem sem interagir além da página de entrada.
- **Breaking change** — Mudança no design system que requer alteração nos consumers.
- **Breakpoint** — Largura de viewport onde o layout muda para se adaptar ao dispositivo.

### C

- **Card sorting** — Método de pesquisa onde participantes organizam itens em categorias para informar IA.
- **Component** — Elemento reutilizável do design system (botão, card, input, etc.).
- **Contrast ratio** — Proporção de luminosidade entre texto e fundo. WCAG AA exige 4.5:1 para texto normal.
- **CTA (Call to Action)** — Elemento que convida o usuário a realizar uma ação específica.

### D

- **Dark mode** — Tema de interface com fundo escuro e texto claro.
- **Definition of Done (DoD)** — Critérios que um item deve atender para ser considerado concluído.
- **Deprecation** — Processo de marcar um componente ou feature como obsoleto antes de sua remoção.
- **Design debt** — Acúmulo de inconsistências e soluções subótimas que degradam a qualidade.
- **Design system** — Coleção de componentes reutilizáveis, padrões e guidelines para construir interfaces consistentes.
- **Design token** — Valor de design armazenado como variável (cor, espaçamento, tipografia).
- **Discovery** — Fase inicial de um projeto focada em entender o problema e o contexto.
- **Double Diamond** — Framework de design com 4 fases: Discover, Define, Develop, Deliver.

### E

- **Edge case** — Cenário de uso incomum ou extremo que deve ser considerado no design.
- **Empty state** — Estado de uma tela ou componente quando não há dados para exibir.
- **Eye-tracking** — Tecnologia que registra para onde o usuário olha na tela.

### F

- **Feature flag** — Mecanismo que permite ativar/desativar features sem deploy.
- **Figma** — Ferramenta de design colaborativo usada pelo squad.
- **Focus state** — Estado visual de um elemento quando recebe foco (keyboard navigation).

### H

- **Handoff** — Processo de entrega de specs de design para desenvolvimento.
- **Happy path** — Fluxo ideal do usuário, sem erros ou desvios.
- **Heatmap** — Visualização de dados que mostra áreas de maior interação na tela.
- **Heuristic evaluation** — Método de avaliação de usabilidade baseado em princípios.
- **Hi-fi (High fidelity)** — Mockup detalhado, próximo do visual final.

### I-J

- **IA (Information Architecture)** — Organização e estruturação de conteúdo.
- **Interaction pattern** — Modelo padronizado de interação (ex: swipe to delete).
- **JTBD (Jobs to Be Done)** — Framework que foca na "tarefa" que o usuário quer realizar.

### K-L

- **KPI (Key Performance Indicator)** — Métrica principal de acompanhamento.
- **Lean UX** — Abordagem que integra design thinking com métodos ágeis.
- **Lo-fi (Low fidelity)** — Wireframe simplificado, focado em estrutura, não em visual.

### M-N

- **Microcopy** — Textos curtos na interface (labels, mensagens, tooltips).
- **MVP (Minimum Viable Product)** — Versão mínima de um produto para validação.
- **NPS (Net Promoter Score)** — Métrica de satisfação e recomendação (-100 a 100).

### O-P

- **OKR (Objectives and Key Results)** — Framework de definição de objetivos e resultados-chave.
- **Persona** — Representação fictícia de um perfil de usuário baseada em pesquisa.
- **Primitive token** — Token de valor bruto (ex: color-blue-500: #1A73E8).
- **Progressive disclosure** — Revelar informação gradualmente conforme necessidade.
- **Prototype** — Versão interativa do design para teste e validação.

### R-S

- **Redline** — Spec visual com medidas exatas de espaçamento, tipografia e dimensões.
- **RFC (Request for Comments)** — Documento de proposta aberto para feedback.
- **Semantic token** — Token com significado contextual (ex: color-action-primary).
- **SemVer (Semantic Versioning)** — Sistema de versionamento: MAJOR.MINOR.PATCH.
- **Skeleton** — Placeholder animado que indica o layout durante loading.
- **Sprint** — Ciclo de trabalho com duração fixa (geralmente 2 semanas).

### T-U

- **Task completion rate** — Percentual de usuários que completam uma tarefa com sucesso.
- **Token** — Ver "Design token".
- **Touch target** — Área tocável de um elemento em dispositivos touch. Mínimo: 44x44px.
- **Tree testing** — Método de pesquisa para validar navegação e hierarquia de informação.

### V-W

- **Verbatim** — Citação literal de um participante de pesquisa.
- **Visual regression** — Teste automatizado que detecta mudanças visuais inesperadas.
- **WCAG (Web Content Accessibility Guidelines)** — Padrão internacional de acessibilidade web.
- **Wireframe** — Representação estrutural simplificada de uma interface.
