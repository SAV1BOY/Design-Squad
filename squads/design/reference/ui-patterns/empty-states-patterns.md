# Empty States Patterns



## Metadata

- **Categoria:** UI Patterns, Onboarding, Engagement
- **Relevancia para o Squad:** Alta — oportunidades de valor frequentemente desperdicadas
- **Ultima revisao:** 2026-03-06



## Summary

Empty states sao telas ou secoes sem conteudo — seja porque o usuario e novo (first-use empty), porque filtrou tudo (no results), ou porque o conteudo foi removido (cleared empty). Cada tipo e uma oportunidade de guiar, educar ou engajar. Empty states genericos ("nada aqui") sao desperdicios de interacao.



## Key Concepts


### 1. First-Use Empty State

O usuario nunca usou esta feature. Oportunidade de: explicar o que a area faz, mostrar o valor de popular, oferecer acao direta (CTA proeminente) e exemplo visual. "Seus projetos apareceram aqui. Crie seu primeiro projeto" com botao e ilustracao.


### 2. No Results Empty State

Busca ou filtragem retornou zero resultados. Oferecer: sugestoes de busca alternativa, links para categorias populares, opcao de resetar filtros, contato com suporte. Nunca so "nenhum resultado" — sempre um caminho adiante.


### 3. Error Empty State

Conteudo deveria estar aqui mas falhou ao carregar. Mostrar: o que aconteceu (de forma simples), o que o usuario pode fazer (retry, verificar conexao), opcao de reportar. Personalidade de marca pode amenizar frustacao mas nao substitui informacao util.


### 4. Completion Empty State

O usuario completou tudo (inbox zero, tarefas concluidas). Momento de celebracao e reforco positivo. "Tudo feito! Voce esta em dia." Opcional: sugerir proxima acao ou conteudo relacionado.


### 5. Illustration and Personality

Empty states sao onde a personalidade da marca mais se destaca. Ilustracoes custom, microcopy com personalidade e animacoes sutis transformam momentos "vazios" em momentos de conexao. Mas substancia primeiro — a ilustracao nao substitui a orientacao.



## Application to Design Squad

- **Empty state audit:** Mapear todos os empty states do produto. Classificar por tipo (first-use, no results, error, completion). Redesenhar os que sao genericos.
- **Empty state template no design system:** Criar template padrao com: ilustracao, titulo, descricao, CTA primario, CTA secundario. Customizavel por contexto.
- **First-use como onboarding:** Tratar cada first-use empty state como micro-onboarding. O que esta area faz? Por que o usuario deveria popular? Como comecar?
- **Personality guidelines:** Definir guidelines de tom e ilustracao para empty states alinhados com a brand persona. Manter consistencia mas adequar ao contexto.
- **Metricas de empty state:** Medir quantos usuarios veem cada empty state e quantos agem no CTA. Otimizar empty states de alta visibilidade.



## Key Takeaways

1. **Todo empty state e oportunidade.** De onboarding, de engajamento, de empatia, de personalidade. Nunca desperdice.

2. **Sempre ofereça caminho adiante.** Nenhum empty state deve ser beco sem saida.

3. **Primeiro utilidade, depois personalidade.** Ilustracao sem orientacao e decoracao. Orientacao sem personalidade e funcional.

4. **Classifique o tipo de empty state.** First-use, no results, error e completion tem necessidades diferentes.

5. **Empty states de alta visibilidade merecem investimento de design.** Se muitos usuarios veem, vale investir em qualidade.
