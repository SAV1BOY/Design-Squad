# About Face — Alan Cooper, Robert Reimann, David Cronin, Christopher Noessel



## Metadata

- **Autores:** Alan Cooper, Robert Reimann, David Cronin, Christopher Noessel
- **Publicacao:** 1995 (4a edicao: 2014)
- **Categoria:** Interaction Design, UX Design
- **Relevancia para o Squad:** Alta — referência completa em interaction design
- **Ultima revisao:** 2026-03-06



## Summary

About Face é a referência mais abrangente em interaction design. Cooper e coautores apresentam um framework completo que vai desde pesquisa com usuários e criação de personas até padrões detalhados de interação para desktop, web e mobile. O livro é organizado em quatro partes: Goal-Directed Design (processo), Design Principles (fundamentos), Interaction Design Details (padrões) e Platform-Specific Guidelines.

A contribuição mais influente do livro é o Goal-Directed Design — uma metodologia que parte de pesquisa etnográfica para criar personas baseadas em dados, cenários de uso e requirements derivados de goals reais dos usuários, não de features imaginadas por stakeholders. Cooper argumenta que a maioria dos softwares é projetada para funcionalidades, não para pessoas, resultando em interfaces poderosas mas inutilizáveis.

A quarta edição expande significativamente a cobertura de mobile, touch interfaces e design responsivo, mantendo os princípios atemporais de interaction design que tornaram o livro referência por duas décadas.



## Key Concepts


### 1. Goal-Directed Design

Metodologia que coloca os goals dos usuários no centro do processo de design. Diferencia life goals (quem o usuário quer ser), experience goals (como quer se sentir) e end goals (o que precisa realizar). O processo segue: Research, Modeling (personas/scenarios), Requirements, Framework, Refinement.


### 2. Personas as Design Tools

Personas não são perfis demográficos — são arquétipos comportamentais derivados de pesquisa que representam padrões reais de uso. Uma persona primária define o alvo principal do design; secundárias são acomodadas sem comprometer a primária. Cooper detalha como criar, validar e usar personas como ferramenta de decisão.


### 3. Scenario-Based Design

Cenários narrativos descrevem como uma persona usa o produto para atingir seus goals. São usados para derivar requirements funcionais e de interação. Cenários de uso diário (daily use), de primeiro uso (first run) e de uso avançado (edge case) cobrem diferentes necessidades do mesmo sistema.


### 4. Interaction Design Patterns

O livro cataloga dezenas de padrões de interação: posture (soberano, transient, parasita), flow patterns, selection patterns, data entry patterns. Cada padrão é contextualizado com quando usar, variações e anti-patterns. Essa seção funciona como referência de consulta rápida.


### 5. Eliminating Excise

Excise é qualquer trabalho que o sistema impõe ao usuário que não contribui diretamente para seu goal. Navegação excessiva, configurações obrigatórias, confirmações redundantes — tudo é excise. Cooper argumenta que bom interaction design minimiza excise agressivamente, mantendo o usuário focado em seu objetivo.



## Application to Design Squad

- **Personas baseadas em dados:** Criar e manter personas do produto derivadas de pesquisa real, não suposições. Revisar personas trimestralmente com novos dados de research.
- **Cenários como spec:** Usar cenários narrativos como complemento às user stories para comunicar contexto e intenção, não apenas funcionalidade.
- **Excise audit:** Periodicamente auditar fluxos do produto contando "passos que não contribuem para o goal do usuário." Cada excise é candidato a eliminação ou automação.
- **Pattern language compartilhada:** Referenciar padrões de interação do livro em design reviews para fundamentar decisões ("estamos usando um sovereign posture aqui porque...").
- **Goal hierarchy em discovery:** Em sessões de discovery, mapear life goals, experience goals e end goals dos usuários para priorizar features que atendem todos os níveis.



## Key Takeaways

1. **Goals, não features, devem guiar o design.** O que o usuário quer realizar é mais importante do que o que o sistema pode fazer.

2. **Personas são ferramentas de decisão, não decoração.** Se a persona não muda decisões de design, está sendo usada errado.

3. **Minimize excise implacavelmente.** Cada clique, cada tela, cada campo que não serve diretamente ao goal do usuário é débito de experiência.

4. **Cenários revelam gaps que user stories escondem.** A narrativa de uso completa expõe contexto, emoção e sequência que uma user story isolada não captura.

5. **Interaction design é uma disciplina com padrões catalogados.** Não reinvente soluções — consulte padrões existentes e adapte ao contexto.
