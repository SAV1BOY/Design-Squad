# New Feature Project Template

## Overview

Template padrao para projetos de novas features no Design Squad.
Este conjunto de documentos guia o time desde o brief inicial ate a
entrega final, garantindo consistencia e qualidade em cada etapa.

## Estrutura do Template

| Arquivo | Descricao | Quando Usar |
|---------|-----------|-------------|
| `brief.md` | Brief da feature | Inicio do projeto |
| `research-plan.md` | Plano de pesquisa | Fase de discovery |
| `design-spec.md` | Especificacao de design | Fase de design |
| `prototype-plan.md` | Plano de prototipagem | Antes de prototipar |
| `handoff-checklist.md` | Checklist de handoff | Entrega para dev |
| `retro-template.md` | Retrospectiva | Pos-lancamento |

## Como Usar

1. Copie esta pasta para o diretorio do seu projeto
2. Renomeie a pasta com o nome da feature
3. Preencha os arquivos na ordem sugerida abaixo
4. Mantenha os documentos atualizados durante todo o ciclo

## Fluxo Recomendado

```
Brief → Research Plan → Design Spec → Prototype Plan → Handoff → Retro
```

## Stakeholders Tipicos

- **Product Owner**: responsavel pelo brief e priorizacao
- **Design Lead**: responsavel pela especificacao e qualidade
- **UX Researcher**: responsavel pelo plano de pesquisa
- **Engineering Lead**: responsavel pelo handoff tecnico

## Requisitos Minimos

Antes de iniciar um projeto de nova feature, certifique-se de que:

- [ ] O brief foi aprovado pelo Product Owner
- [ ] O time de design foi alocado
- [ ] O timeline foi definido e comunicado
- [ ] Os stakeholders foram identificados
- [ ] O canal de comunicacao foi criado (Slack channel, etc.)

## Convencoes de Nomenclatura

- Use `kebab-case` para nomes de arquivos
- Prefixe assets com o nome da feature: `feature-name-asset-description`
- Versione prototipos com sufixo: `v1`, `v2`, `v3`

## Ferramentas Recomendadas

| Etapa | Ferramenta |
|-------|------------|
| Design | Figma |
| Prototipagem | Figma / ProtoPie |
| Research | Maze / UserTesting |
| Documentacao | Notion / Confluence |
| Handoff | Figma Dev Mode / Zeplin |

## Metricas de Acompanhamento

Para cada feature, rastreie as seguintes metricas:

- **Lead time**: tempo do brief ate o lancamento
- **Design iterations**: numero de iteracoes de design
- **Usability score**: pontuacao de usabilidade pos-teste
- **Stakeholder satisfaction**: satisfacao dos stakeholders
- **Bug count**: numero de bugs relacionados a UI/UX
