# Phase: Feature Brief

## Objective

Definir escopo, contexto e criterios de sucesso para uma nova feature de produto. O brief alinha stakeholders e serve como referencia durante todo o projeto.

## Inputs

- Request de produto (PM/stakeholder)
- Dados de uso atuais (analytics)
- Feedback de usuarios (support tickets, NPS comments)
- Roadmap e prioridades do trimestre
- Constraints tecnicas conhecidas

## Activities

### 1. Problem Definition
```
- Qual problema estamos resolvendo?
- Para quem? (persona, segmento)
- Qual evidencia temos de que este problema existe?
- Qual o impacto de NAO resolver?
```

### 2. Scope Definition
```
- O que esta DENTRO do escopo (in scope)
- O que esta FORA do escopo (out of scope)
- Quais decisoes ja foram tomadas (constraints)
- Quais decisoes ainda precisam ser tomadas
```

### 3. Success Criteria
```
- Metrica primaria: [o que medimos]
- Baseline: [valor atual]
- Target: [valor esperado]
- Timeline: [quando medimos]
```

### 4. Stakeholder Alignment
```
- Workshop de kickoff com PM, Eng Lead, Design Lead
- Revisar brief em grupo
- Documentar decisoes e premissas
- Assinatura de escopo (sign-off)
```

## Output

- Feature brief documentado e aprovado
- Metricas de sucesso definidas
- Timeline estimada
- Equipe alocada
- Riscos e dependencias mapeados
