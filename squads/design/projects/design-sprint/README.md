# Design Sprint Project Template

## Overview

Template para conducao de Design Sprints, baseado na metodologia
do Google Ventures (GV). O sprint de 5 dias permite ao time ir
do problema a solucao validada em uma semana.

## Estrutura do Template

| Arquivo | Descricao | Dia |
|---------|-----------|-----|
| `day1-understand.md` | Entender o problema | Segunda |
| `day2-diverge.md` | Divergir em solucoes | Terca |
| `day3-decide.md` | Decidir a abordagem | Quarta |
| `day4-prototype.md` | Prototipar a solucao | Quinta |
| `day5-validate.md` | Validar com usuarios | Sexta |

## Pre-Sprint Checklist

Antes de iniciar o sprint, garanta que os seguintes itens estao
prontos. A preparacao adequada e critica para o sucesso do sprint.

### Logistica

- [ ] Sala reservada para a semana inteira
- [ ] Materiais preparados (post-its, canetas, timer, quadro branco)
- [ ] Ferramentas digitais configuradas (Miro/FigJam, Zoom se remoto)
- [ ] Almoco e snacks organizados (evitar interrupcoes)

### Pessoas

- [ ] Decider identificado e confirmado
- [ ] Facilitador designado e preparado
- [ ] Time de 5-7 pessoas confirmado
- [ ] Usuarios para teste de sexta recrutados (5 participantes)
- [ ] Especialistas para lightning talks de segunda agendados

### Conteudo

- [ ] Briefing do desafio preparado
- [ ] Dados de pesquisa anteriores compilados
- [ ] Metricas relevantes levantadas
- [ ] Desk research sobre concorrentes feito
- [ ] User personas atualizadas

## Papeis no Sprint

| Papel | Responsabilidade | Pessoa |
|-------|-----------------|--------|
| **Decider** | Toma decisoes finais quando nao ha consenso | [Nome — geralmente PO ou lider] |
| **Facilitador** | Conduz atividades, controla tempo, mantém foco | [Nome — geralmente designer senior] |
| **Time** | Participa ativamente de todas as atividades | [Nomes — mix de disciplinas] |
| **Especialistas** | Fornecem conhecimento especifico (day 1 only) | [Nomes] |

## Agenda Semanal

| Dia | Foco | Horario | Entregavel |
|-----|------|---------|-----------|
| Segunda | Understand | 10h-17h | Mapa + Target |
| Terca | Diverge | 10h-17h | Solucoes individuais |
| Quarta | Decide | 10h-17h | Storyboard |
| Quinta | Prototype | 10h-17h | Prototipo testavel |
| Sexta | Validate | 10h-17h | Insights validados |

## Regras do Sprint

1. **Sem dispositivos** durante as atividades (exceto o facilitador)
2. **Time-boxed**: respeitar rigorosamente os tempos de cada atividade
3. **Trabalho individual antes de grupo**: ideacao silenciosa primeiro
4. **Sem hierarquia**: todas as ideias tem o mesmo peso
5. **Decider desempata**: quando nao houver consenso
6. **Foco no usuario**: toda decisao deve considerar o usuario final
7. **Prototipo descartavel**: o prototipo nao precisa ser perfeito

## Metricas de Sucesso do Sprint

| Metrica | Como Medir |
|---------|-----------|
| Validacao da hipotese | Resultado dos testes com usuarios |
| Alinhamento do time | Survey pos-sprint |
| Velocidade de decisao | Tempo para chegar ao consenso |
| Qualidade do prototipo | Feedback dos participantes de teste |
| Satisfacao do time | NPS interno pos-sprint |

## Pos-Sprint

### Entregaveis Finais

- [ ] Documentacao do sprint (fotos, anotacoes, decisoes)
- [ ] Prototipo finalizado (link do Figma/ferramenta)
- [ ] Resultados dos testes com usuarios
- [ ] Recomendacoes de proximos passos
- [ ] Retrospectiva do sprint

### Possibles Outcomes

| Resultado | Proximo Passo |
|-----------|--------------|
| Hipotese validada | Iniciar design detalhado |
| Hipotese parcialmente validada | Iterar e testar novamente |
| Hipotese invalidada | Pivotar e replanejar |
