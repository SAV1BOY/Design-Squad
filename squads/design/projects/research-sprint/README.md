# Research Sprint Project Template

## Overview

Template para conducao de Research Sprints — ciclos rapidos e
focados de pesquisa com usuarios para gerar insights acionaveis.
Diferente de um projeto de pesquisa tradicional, o research sprint
e time-boxed e orientado a decisao.

## Estrutura do Template

| Arquivo | Descricao | Fase |
|---------|-----------|------|
| `research-brief.md` | Brief de pesquisa | Planejamento |
| `participant-screener.md` | Screener de participantes | Recrutamento |
| `synthesis-template.md` | Template de sintese | Analise |
| `insights-report.md` | Relatorio de insights | Entrega |

## Como Usar

1. Defina o objetivo e escopo no brief de pesquisa
2. Use o screener para recrutar participantes adequados
3. Conduza as sessoes de pesquisa (entrevistas, testes, etc.)
4. Sintetize os dados usando o template de sintese
5. Consolide insights no relatorio final

## Fluxo do Projeto

```
Brief → Screener → Recrutamento → Coleta → Sintese → Insights Report
```

## Tipos de Research Sprint

### Discovery Sprint (1-2 semanas)

Objetivo: Entender o problema e o contexto do usuario.

| Atividade | Duracao | Participantes |
|----------|---------|---------------|
| Desk research | 2 dias | Researcher |
| Entrevistas exploratórias | 3-5 dias | 6-8 usuarios |
| Sintese e report | 2-3 dias | Research team |

### Evaluative Sprint (1 semana)

Objetivo: Avaliar uma solucao existente ou prototipo.

| Atividade | Duracao | Participantes |
|----------|---------|---------------|
| Preparacao | 1-2 dias | Researcher + Designer |
| Testes de usabilidade | 2-3 dias | 5-8 usuarios |
| Sintese e report | 1-2 dias | Research team |

### Generative Sprint (2 semanas)

Objetivo: Explorar novas oportunidades e necessidades.

| Atividade | Duracao | Participantes |
|----------|---------|---------------|
| Contextual inquiry | 3-5 dias | 5-8 usuarios |
| Co-creation sessions | 2-3 dias | 4-6 usuarios |
| Sintese e report | 3-4 dias | Research team |

## Principios do Research Sprint

1. **Time-boxed**: duracoes fixas para cada fase, sem extensoes
2. **Decision-oriented**: toda pesquisa deve informar uma decisao
3. **Collaborative**: o time de design participa da coleta e sintese
4. **Bias-aware**: multiplos observadores para reduzir vies
5. **Actionable**: insights devem ter recomendacoes claras

## Ferramentas Recomendadas

| Fase | Ferramenta | Uso |
|------|-----------|-----|
| Recrutamento | [Respondent / UserTesting] | Encontrar participantes |
| Agendamento | [Calendly / Cal.com] | Agendar sessoes |
| Conducao | [Zoom / Lookback / Maze] | Sessoes remotas |
| Notas | [Dovetail / Notion] | Registro de observacoes |
| Sintese | [Miro / FigJam] | Affinity mapping |
| Report | [Notion / Google Slides] | Apresentacao |

## Metricas de Sucesso

| Metrica | Como Medir |
|---------|-----------|
| Participantes recrutados vs. meta | N recrutados / N planejado |
| Taxa de no-show | N no-shows / N agendados |
| Insights acionaveis | N insights com recomendacao clara |
| Decisoes informadas | N decisoes que usaram os insights |
| Tempo de entrega | Dias do brief ao report final |
| Satisfacao dos stakeholders | Survey pos-entrega |

## Etica em Pesquisa

- Sempre obter consentimento informado antes da sessao
- Garantir anonimidade dos participantes no relatorio
- Oferecer compensacao justa pelo tempo dos participantes
- Permitir que participantes abandonem a sessao a qualquer momento
- Armazenar dados de pesquisa de forma segura (LGPD compliance)
